# Changelog

## Unreleased

### Changed

#### Compositor and rendering

- A node's `effects` list now takes three more kinds, and a window's style writes them instead of reporting them `not applied`. A `shadow` with `inset` is an inset shadow (the pass is named `inset-shadow`), a `background` is one colour filling the node's rounded shape below its content, and a `filter` blurs and grades everything the node paints (`blur_radius`, `saturation`, `brightness`, `contrast`). A node holds at most 8 inset shadows, one background and one filter. A renderer that does not draw one names it in the node's `skipped` as `<kind>: unsupported-by-renderer` and leaves it out of the seat's `effect_kinds`; the next entry says which renderer draws which. `gnoblin_render::Shadow` gains `inset`, `Pass` gains `Background { color }` and `Filter(FilterParams)`, `Pass::NAMES` gains `inset-shadow`, `background` and `filter`, and `GnoblinEffect.kind` gains `EFFECT_BACKGROUND` (5) and `EFFECT_FILTER` (6) within ABI 1.0; `Effect::new(EffectKind::Filter)` starts with a blur radius of 0. The style's `background`, the blur and grades of its `filter` and its inset shadows become effects; a `filter`'s blurs add as Gaussians and its grades multiply (lane C1 of the Vulkan renderer design; `crates/gnoblin-render-vulkan/DESIGN.md`, section 6.4).
- The three renderers now draw the same effects and are held to the same golden pictures (`crates/gnoblin-render-frame/tests/golden/`). GLES draws every kind, including an inset shadow, a `background` and a `filter`'s grades and blur. The Vulkan renderer draws a shadow, an inset shadow, a border, a `background` and a `filter`'s grade; it does not draw a blur yet, so `blur` is not in its `effect_kinds` and a `filter` that blurs is drawn graded and named `filter: unsupported-filter-blur` in the node's `skipped`. The software renderer computes a blur (with its `downscale`, reduced as GLES reduces it), smooth shadows, an inset shadow, anti-aliased borders and corners, a `background` and a `filter`'s grades and blur on the CPU, and holds all 14 shared golden cases; only a shell's `shader` is not drawn there, because it needs a WGSL compiler and a GPU. An outer shadow now fades with its layer's opacity on all three, and the software renderer redraws a whole blurred layer when damage reaches its blur. `RendererKind::effect_kinds` and the renderer tables of `docs/guides/window_effects.md` and `docs/js-style.md` say what each draws.
- The three standard capture protocols, `ext_image_capture_source_v1`, `ext_image_copy_capture_v1` and `zwlr_screencopy_v1`, are crates of their own under `crates/protocols/` (lane CaptureMove; design/protocol-crates.md). They advertise the same globals at the same versions and in the same order, and the capture engine and the View source stay in `gnoblin-wayland`.
- Window opacity from `wp_alpha_modifier_v1` and window rules now combines into the window's scene node, and a closing window keeps the opacity it had when its close fade began.
- The compositor now applies `appearance.reduced-motion` from the accepted document it starts with, as it does when a document is committed. Before, a session whose stored document asked for reduced motion animated until something committed a document, which a Rust or a Python shell never does (lane CompShaders, bead gnoblin-6qzc; `crates/gnoblin-compositor/src/lib.rs`, `crates/gnoblin-compositor/tests/tree_ipc.rs`, `crates/gnoblin/tests/modular/native_root.rs`).

#### Errors

- A failed call of an object of the library now reaches Rust, Python and TypeScript shells with a `code` from the one set of `docs/shell-api/errors.md` (`not_found`, `already_exists`, `read_only`, ...) and a `target`, `Class#id.member`. In TypeScript and Python it is a `GnoblinError`; in Rust, `Fail::code()` and `Fail::target()`. A bad argument is still a `TypeError` or a `RangeError`, with no code. The code reaches the client through a `last_error_code` field appended to `GnoblinObjectApi` within ABI 1.0 (the table grew from 152 to 160 bytes), which a client reads only when the table has it; the integer a call returns is unchanged (lane ErrCodes, bead gnoblin-r6ze, issue #403; `examples/39-native-errors`, `docs/shell-api/errors.md`, `docs/abi-compatibility.md`).
- A shell that read the old failure changes in five ways (`docs/shell-api/errors.md`, "A shell that read the old failure"). `error.code` of a failed object call in TypeScript is the word (`"not_found"`), where it was the ABI's integer; the integer is `abi` on the error of the native module only. The message no longer begins with the symbol of the ABI code (`E_TYPE: `, `E_REFUSED: `) in TypeScript and Python. A write to a read-only property or collection is a `GnoblinError` with the code `read_only` in TypeScript and Python, where it was a `TypeError`. So are a timed write to a property that cannot animate (`unsupported`, reached only through the native module) and `Display.viewport` on a display that already shows a viewport (`busy`).
- A refusal of the object server now names the member in the spelling of the language that made the call, where it named the schema's snake_case in every language (lane E904, bead gnoblin-e904). In TypeScript a write of `gnoblin.compositor.userShaders` (`gnoblin.compositor.user_shaders` in Python, `set_user_shaders` in Rust) refused for its type says `` `CompositorSettings.userShaders` must be a boolean, got text``, and a refused argument of `splitRatio` says `` `DwindleLayout.splitRatio`: `amount` ``. In Python the member is the attribute of the class (`CompositorSettings.user_shaders`, `from_` for the member `from`). Rust and the compositor's log keep the schema's name. The generated classes carry a table of their members' spellings (`spell_<class>` in JavaScript, `_spell_<class>` in Python; `crates/gnoblin-sdkgen/src/object_js.rs`, `object_py.rs`) that `B.raise` and `_B.named` read to rewrite the library's words; the library's own text is unchanged (`docs/shell-api/errors.md`, "Member names in a refusal").

#### Windows, workspaces and shell

- A listener's `onAdded` can now use the library's members on the window it is given. `ClientState.of(client)`, `client.floatingBounds`, `workspace.clients.add(client)` and the like failed with "node N is not a client" there, because the core announced a new window to the shell's listeners before the library's own subscription to the same tree change had heard of it. The library now takes the window in the first time a shell hands it over. A script that wrote a new window's rectangle and `floatingBounds` in `onAdded` therefore keeps the window there: the floating layout leaves a window with floating bounds where it is, where it used to place the window again, at the first free space (`crates/gnoblin-std-impl/src/events.rs`, `crates/gnoblin-std-impl/src/object/client.rs`, `crates/gnoblin-js/tests/workspaces.rs`).
- A turn that only a window's title changed no longer reads every window of every workspace. The layout pass read each window's focus, fullscreen and maximised flags, its rectangle and whether it was alive before it asked whether a workspace had anything to compute, which made a frame with one title change cost 34% to 56% more than before the layout moved into the library. A workspace whose members, area, gaps, layout options and window flags are as the last pass saw them is now left alone, a dropped placement is looked for only in the windows whose placement has not been seen held, a window's liveness is asked only when there is a style or a visibility to write, and a fullscreen or maximised flag that a pass read as the library had written it, which the compositor then refuses or drops after the gate's resends, is read again once the compositor has answered, because nothing else says it is as it was. The library's half of that frame at 25, 100 and 300 windows went from 119-130, 259-269 and 656-730 µs to 86, 143-149 and 294-343 µs, and a frame with one title change on a laid-out session from 420, 819 and 1987 µs to 309, 435 and 889 µs (lane TitleGate; `crates/gnoblin-std-impl/src/turn.rs`, `crates/gnoblin-js/tests/turn_scans.rs`, `crates/gnoblin-js/tests/frame_cost.rs`).
- The `DwindleLayout` split direction now follows its cell's shape on every layout, so taller cells split top and bottom, unless `preserveSplit: true` or an explicit `split` is set.
- A member of `libgnoblin-std` that takes a window now takes the core's `Client` object instead of its id as text, in all three languages: `Client` in TypeScript, `gnoblin.objects.model.Client` in Python and `&gnoblin_core::objects::Client` in Rust (lane H9ot, beads gnoblin-h9ot and gnoblin-kcg1; docs/sdk-generator.md, `examples/36-native-clients`). Examples are `decorations.insetOf(client)`, `menus.show(client, x, y)` and `workspace.clients.add(client)`. An id as text, or an object of another class, is a `TypeError` in TypeScript and Python and a build error in Rust. A window that has closed fails the member with `the client is gone`. `clients.get(id)` gives the `Client` of an id.
- One object of a library is now one script object in TypeScript and Python, and two Rust values of it are equal. Two reads of an object, or two events that carry it, used to give two wrappers, so `===`, `indexOf`, `is` and map keys did not match them. Now `gnoblin.clients === gnoblin.clients`, and a Rust handle implements `PartialEq`, `Eq` and `Hash` by the object it holds (lane C13ep, bead gnoblin-13ep, issue #419; docs/sdk-generator.md, docs/typescript-shell.md, docs/python-shell.md).
- The workspace classes of `libgnoblin-std` now report a window as the core's `Client` object instead of its id as text, in all three languages: a collection's `members` and its `added` and `removed` events, a workspace's `client_added` and `client_removed`, and a layout's `children`, `focused` and `node`. It is the same object `clients.get(id)` gives, so a shell compares it with `===`, `is` or `==` and reads its title through the core. A shell that read the id from these values reads `client.id` instead. The frame, menu, policy and shell classes still report a window as its id as text (lane C13ep, bead gnoblin-13ep, issue #419; docs/typescript-shell.md, docs/python-shell.md, docs/rust-shell.md, `examples/36-native-clients`).

#### Input, seats and accessibility

- The `gnoblin-xr` pointer's seat is now named `xr` instead of `gnoblin-xr-pointer`, reusing an existing `xr` seat when one is present.
- The stock shell now receives pointer and touch input on windows, so `Window:on_enter`, `on_motion`, `on_leave`, `on_press` and `on_release` run on the real compositor and focus follows them, while clients still get the input.

#### Session, services and recovery

- The strike policy, file watcher, spawn handling and reload logic moved from `gnoblin-js` into `gnoblin-shell-host`, and the JavaScript shell behaves as before.
- Attaching the tree shell from a connection lacking the owner grant now fails with `not-owner` (`failed_op` -1) instead of `not-privileged`, while transactions from non-holders still return `not-privileged`.
- Calls to `gnoblin.session.suspend()`, `hibernate()`, `reboot()` and `poweroff()` now report logind's actual answer, returning `{accepted = true}` or an error such as `denied`, `unsupported`, `busy`, `unavailable`, `timed_out` or `internal`.

#### Configuration

- Custom shaders are now enabled by default; set `compositor.user-shaders = false` to switch them off, which takes effect at the next login.
- `Output.apply` and `Output.mirror` now return an `Operation<Output>` that succeeds with the output or fails with the compositor's error message and code, replacing the polled `OutputApplication` with `done` and `error`.
- Sets `client.frameInset` to a four-sided `FrameInset` (`top`, `right`, `bottom`, `left`) instead of a titlebar height, so layout, placement, drags and snaps keep room on all sides.
- Layouts with `extent = "unbounded"` must now declare `kind = "tiling"`, and placements outside the output or past the coordinate bound refuse the whole reply.
- A `Process` now emits `closed` like Window, Workspace and Output, with `alive`, `status`, `exit_code` and `signal` describing how it ended, while `wait()` and `kill()` remain.

#### Client protocols and compatibility

- The JavaScript API now uses one set of snake_case error codes via `ErrorCode` from `gnoblin/errors`, replacing the mixed kebab-case, snake_case and host-specific codes.
- X11 windows now appear to the shell as `window` nodes like Wayland toplevels, with title, app ID, size and focus published, and closing them ends their captures and frames; servers older than Xwayland 23.1 still get no node.
- Xwayland windows now get Gnoblin's own frame, rules and effects like Wayland windows, with `frame.mode = "auto"` as the default for X11 windows that do not disable decorations.
- Gnoblin's control wire operations now come from one shared table, with no wire change and the API still at version `1.92`.
- Live `Tween`, `Process` and `AnimationPreview` objects now share one subscription model: `on("closed")` reports the outcome, `watch` accepts only changeable fields, `gnoblin.input.on` returns a `Subscription` you can `unsubscribe()`, and a config reload ends all runtime-owned objects.
- The generated object classes take the shell API's names in every language: `camera2d`, `camera3d`, `style`, `device`, `idle` and `launches` are now `Camera2D`, `Camera3D`, `ClientStyle`, `InputDevice`, `IdleMonitor` and `LaunchFeedback` in JavaScript, Python (`gnoblin.objects`) and Rust (`gnoblin_std::objects`, `gnoblin_core::objects`).

#### Command line and tooling

- The isolated shell now logs under the role `shell` instead of `runtime`, shown as `shell/component` on the console, `gnoblin-shell` in the journal, `GNOBLIN_ROLE=shell`, and selectable with `gnoblinctl log --role shell`; older records keep `runtime`.

#### Packaging and install

- Packages now accept pre-release versions: the source bundle keeps the SemVer spelling (`0.1.13-nightly.…`), while RPM packages use `0.1.13~nightly.…`, and release versions are unchanged.
- `cargo build -p gnoblin` no longer prints a build-script warning on every build that `libgnoblin-core.so.1` is not beside the binary yet. A workspace build reaches the launcher's script before the core's has named the library, so the warning was wrong for the builds CI runs and noise for every build that never runs the binary; `CONTRIBUTING.md` still says to stage the tree first.

#### Documentation and tests

- The events documentation now says that a window which opens and closes inside one batch of what the compositor published is told of neither way, and example 39 logs a line when its shell is told a window appeared, which its test waits for before closing the window; the test closed the window as soon as the compositor published it and sometimes saw no closed window (bead gnoblin-7f4v; `docs/events/desktop-state.md`, `examples/39-native-errors`).
- The JavaScript shell's frame stages are now listed in a table with their ordering requirements recorded and tested, with no change in behaviour.
- The location settings page now says how to allow the `gnoblin` agent in GeoClue's `[agent]` whitelist, with the drop-in to save (also in the source tree as `packaging/geoclue/50-gnoblin.conf`).
- A documentation page can show one example in TypeScript, Python and Rust as tabs (`::: tabs`, bead gnoblin-tvq1; `docs/documentation-site.md`). `cargo xtask docs-examples` checks each example in its own language (`tsc` and `pyright` against the installed declarations and stubs, `cargo check` against the SDK crates), and a failure names the page and the line. `docs/shell-api/idle.md` is the first page converted. The link from `docs/typescript-shell.md` to its object-classes heading names the heading's real anchor.
- The website has an API reference for each SDK, made by that language's own documentation tool and served as its own HTML: TypeDoc over the TypeScript declarations at `/reference/typescript/`, Sphinx with `sphinx-autoapi` over the Python stubs at `/reference/python/`, and rustdoc over `gnoblin-core`, `gnoblin-std` and `gnoblin-macros` at `/reference/rust/`. They replace the Markdown reference pages the build wrote before. The comments above each class, property, method, signal and enum in the schema files are now the TSDoc comments, the Python docstrings and the Rust doc comments of the generated SDKs, so a description is the same sentence in all three references and in an editor's hover text. `yarn build` in `infra/site` makes the three (Python 3.11 or later is needed for the Python one), `cargo xtask docs-reference` writes the declarations the TypeScript and Python tools read, and `docs/reference/index.md` leads to them (lane RefDocs; `docs/documentation-site.md`, `docs/sdk-generator.md`).
- The GPU memory soak runs the stock shell. It started the JavaScript shell without the core's natives, so the shell panicked at start, the thread's panic was thrown away and every renderer's soak passed with no shell. It now starts the shell as `js_shell.rs` does, checks it is alive every cycle, and requires its own script to have counted the stock entry's workspaces and the windows the churn opened. Its `capture_frames_failed` is accounted for and asserted: a session lock ends the capture session, and the one frame wanted of it is refused.
- The test harnesses that run the compositor or the shell in a thread (`gpu_memory_soak`, `support/lock_session.rs`, `js_shell.rs`, the compositor tests' `Session`, the Vulkan renderer's shm client and the load threads of `budgets.rs`) raise a panic of that thread as the test's failure, with its own message, instead of joining it and dropping the result. A test that is already unwinding keeps its own failure, since a second panic from a destructor aborts the process.
- `just ext-deny` checks the extension workspace against `extensions/gnoblin-xr/deny.toml`: the root `deny.toml` carries licence exceptions and a git source only the root workspace uses, which made every extension run warn that they were unmatched. The three duplicate crates of that workspace (`hashbrown`, `libloading`, `syn`) are recorded with their reasons.
- `just deny` of the root workspace prints no warning. The cargo-deny graph is the two Linux targets Gnoblin is built for, so the Windows-only crates (`windows-sys`, the `windows_*` target crates, `hermit-abi`) are no longer counted; `prost` is at 0.14.6, which drops a duplicate `itertools`; and each duplicate version left has a `skip` entry in `deny.toml` that names the crates asking for each version and why no release makes them agree.

### Added

- `GnoblinApi` has `node_effects_serial(ctx, node, out)`, and the Rust SDK `Node::effects_serial()`: the serial of the last write of a node's `effects` that the shell made, zero when it made none. The effects themselves are not carried out by `node_get`, so a library that wrote a list could not tell whether it was still the node's (lane VrnwReload; Beads `gnoblin-vxi3`; appended within ABI 1.0, table 480 to 488 bytes; `crates/gnoblin-core-impl/src/{session,tree,table}.rs`, docs/abi-compatibility.md).
- `gnoblin.compositor.userShaders` (`user_shaders` in Python and Rust) of the generated core can be written, as the TypeScript library's can (lane CompShaders, bead gnoblin-61nn; `crates/gnoblin-core-abi/schema/session.toml`, `crates/gnoblin-core-impl/src/model/input/settings.rs`). The settings ledger that holds what a shell wrote to the devices now holds the compositor's setting too, and the `document` of `gnoblin.input` has it as `{"compositor":{"user-shaders":false}}` after the `input` section, so the JavaScript runtime commits it with the shell's configuration and it takes effect at the next login. Until then the property reads what the shell wrote, and the new `gnoblin.compositor.reset("user_shaders")` takes it back to the default and reads what the running compositor holds (a generated property cannot be written none, so the method is the way back, as it is on a device). A value that is not a boolean is refused and leaves the setting. A Rust or a Python shell commits no document, so for them the write is kept in `gnoblin.input.document` and readable but nothing commits it.
- The std library adds `workspaces`, `displays`, `scene`, `gestures` and `requestTransition` to the core's `gnoblin` root, and `profiles` to its output collections, when it is loaded (lane ZfStd, bead gnoblin-zf1l; docs/sdk-generator.md, example 37). The std schema declares them with `[[augment]]` and `target = "core.<class>"`: the catalog checks the target and refuses a missing one and a name the core's class has, the core catalog never reads the std files, and a shell that loads no std has none of the members (the attribute is missing in TypeScript and Python, the Rust extension traits `ModelRootStdExt` and `OutputCollectionStdExt` of `gnoblin_std::prelude` are not in scope, and `readelf -d` of a core-only shell names no std library). Importing `gnoblin-std/generated/objects` defines them on the core's class, importing `gnoblin.objects.std` sets them on it, and each is read through the std library of the generation that is running, so a reload binds them to the new one. The std classes `workspaces` (`area`, `show`, `show_by_id`), `displays` (the list and `replace`) and `output_profiles` are new.
- The generated `gnoblin` root of the core has the members the TypeScript library's has: `timers.after(ms, fn)` and `timers.now()` replace the root's `timer` and `now`, `version()` is a method and no longer a property, `motion(duration)` answers 0 while the main seat asks for reduced motion, `compositor.userShaders` reads whether the compositor accepts shaders, and `find(kind, filter)` lists `Window` and `Output` objects by a table of fields or, in JavaScript, TypeScript and Python, a function, and refuses a kind the core does not list with the kinds that work. Rust has `timers()`, `version()`, `motion`, `compositor()` and `find::<Client>` (lane ZfCore, bead gnoblin-zf1l; docs/sdk-generator.md, example 35). A schema method can name its kind with `find = "Kind"`.
- The generated SDKs have value classes for every record of the std and core catalogs, and the same names, fields and defaults in each language: `Border`, `Shadow` and the rest are classes with a constructor option bag in TypeScript, `dataclass`es in Python and structs with `Default` in Rust. A record can be the family of a tagged value in the catalog (`tag` and `[[object.variant]]`), and the style filter is one: `BlurFilter` (radius 12), `SaturateFilter`, `BrightnessFilter`, `ContrastFilter` and `ShaderFilter` are classes in all three languages (a union in TypeScript and Python, the enum `Filter` in Rust), and the wire carries the same `filter` record as before (bead gnoblin-hyvr; docs/sdk-generator.md). In JavaScript a record read from the library is now an instance of its class and not a plain object, and a call that takes a filter takes an instance of one of the classes.
- The toolkit's bare functions without a native implementation are functions of classes of `libgnoblin-std` (lane StdFns; gnoblin-8aq2, part b; `crates/gnoblin-std-impl/src/ui/{classes,session}.rs`, `crates/gnoblin-std-abi/schema/ui.toml`). `Ui.estimateText(text, size)` answers the size a text takes while it cannot be measured (`estimateText`), and `Ui.encodePaintList(ops)` answers the bytes of a canvas's `content` for a list of paint operations (`encodePaintList`), refusing the whole list with `draw op N: ...` when one operation is bad. `Toast.show`, `Launcher.open` and the swipe and pinch action bindings with `Gestures.direction` were already native; examples 31 and 32 now call each of them from Rust, TypeScript and Python, and the TypeScript and Python shell pages map the bare functions to them.
- A JavaScript or TypeScript shell runs on one stock library, chosen from its static imports before any of it runs (lane NpFlip; `crates/gnoblin-js/src/choice.rs`, docs/typescript-shell.md). A shell that imports only the generated object modules runs on the generated classes, and every other shell runs on the TypeScript library as before. A reload that would change the library is refused and the running shell keeps serving.
- `gnoblin-core/generated/objects` exports `gnoblin`, the root of the core's object model, with a named subscription for each of its signals (`gnoblin.onClientCreated(handler)`).
- The Rust SDK of `libgnoblin-std` calls the generated classes for workspaces, clients, collections, layouts and dividers, and example 34 with `modular::native_workspaces` (lane NpStdObjects, slice 4; design/native-std-port.md, 2.10; `crates/gnoblin-std/src/{workspace,collection,client,client_state,desktop,layout,builtin,split,subscription}.rs`, `examples/34-native-workspaces`). `Workspace`, `Collection`, `Client` and `Layout` keep their names and go through the object protocol, so Rust, Python and TypeScript see one set of workspaces. A selection of clients takes the keys of `client_query`. The example makes two workspaces, gives the first each layout of the library and one of its own, drags a divider with a pointer binding of the core, and a stock `ext_workspace_manager_v1` client reads the active workspace.
- The window policy is native in `libgnoblin-std` (lane NpStdPolicy; design/native-std-port.md, JS6 and JS15; `crates/gnoblin-std-impl/src/policy/`, `crates/gnoblin-std-abi/schema/policy.toml`, `examples/32-native-policy`). `focus_policy` runs the focus modes, raise on click, auto raise and the pointer rest from the seat's settings; `window_state` routes the requests of windows to listeners the shell adds (the first that handles one answers, the stock answer runs last) and answers maximise, fullscreen, minimise, activate, raise, lower, close, move and resize; `repositioning` moves and resizes a window with the arrow keys; `snap` names the edge zones; `move_binding`, `resize_binding`, `swap_binding`, `split_resize_binding`, `swipe_action_binding`, `pinch_action_binding` and `workspace_slide_binding` install on an input context of the core. Each service does nothing before its `start`, so a shell with a policy of its own is not answered twice. The window menu's Move and Resize use the keyboard modes when they are started. The TypeScript policy under `data/js` is unchanged until the switch.
- Output profiles, displays and viewports are native in `libgnoblin-std` (lane NpStdDisplay; design/native-std-port.md, JS10; `crates/gnoblin-std-impl/src/display_objects/`, `crates/gnoblin-std-abi/schema/display.toml`, `examples/33-native-displays`). `output_profile` (`match`, `id`, `settings`, `format_mode`), `viewport` (`content`, `camera`, `clear_color`), `display` (`selectors`, `mode`, `outputs`, `viewport`) and the `display_manager` service (the lists, add, remove, replace, `display_at`, `snapshot` and `restore`, and the signals `changed`, `applied` and `noted`) are classes of the object protocol over the state the std table's `profile_*` and `display_*` functions use. The checks and their words are the TypeScript classes'. A transition that does not commit puts back the workspace each desk shows, the displays' waiting workspaces and the viewports' cameras and colours. `tests/displays.rs` replays the 24 cases of the TypeScript display tests, and `modular::native_displays` runs example 33 in a real session. The generated Rust API writes a property named with a keyword as a raw identifier (`r#match`) and builds its helpers from the plain name.

#### Compositor and rendering

- An idle output now draws a shader pass as soon as it is ready, and a struck pass returns after its ten seconds without needing another repaint.
- Shader sources that run over budget are now switched off for 10 seconds after three consecutive frames above 50 ms, and refused for the session after three strikes, showing `shader: over-budget` or `shader: refused-for-session` in `skipped`.
- The Vulkan shader pass now compiles pipelines on a worker thread, so the first frame using a new shader source draws without it (reported as `shader: compiling`) instead of stalling, and the output is redrawn once it is ready.
- Fixed the Vulkan renderer using an out-of-range dynamic offset for passes without a shader block when a frame contains multiple plans.
- The Vulkan renderer now supports custom shader passes on layers, with `RendererKind::Vulkan` listing `shader`; sources that fail to compile or whose pipeline the driver refuses are drawn without the pass and reported in the frame's shader timings.
- Adds a `ShaderFilter` style element in Rust, TypeScript and Python that applies a custom shader pass to a window, drawn after the backdrop blur and before shadows, up to four per style, and only while `user_shaders` is enabled.
- Adds a `shader` effect kind that accepts validated WGSL source and up to 8 params, gated behind the off-by-default `compositor.user-shaders` setting; accepted shaders are reported as `skipped` since no renderer draws them yet.
- The GLES renderer now draws the `shader` effect, with passes chained in order, backdrop capture, and a compile failure skipping the pass instead of the frame.
- Gnoblin can now build as a core without std code, with the stock window manager moved to `gnoblin-std-wm`; the `std-providers` feature is on by default, so the standard desktop behaves as before.
- A shell holding the tree can now turn off the compositor's own window animations with the seat's `builtin_motion` (default `true`), and set each window's `frame_policy` (`auto`, `hold` or `throttle`) with `frame_rate` (30 Hz default) and `report_presented`.
- Gnoblin now enforces a GPU memory budget: clients past `compositor.client-memory-limit-mib` or `compositor.client-surface-limit`, or any change the budget cannot hold, are disconnected with `no_memory`, after releasing caches first.
- Each output's screen node now publishes read-only `gpu_memory_bytes` and per-category GPU memory figures, and fixes stop the GLES renderer from leaking textures and the Vulkan renderer from holding staging memory.
- The JavaScript shell now skips idle frames, so an idle frame drops from over 100 µs to under 1 µs, with `entry.wake()` available to request a frame on a timer.
- Windows can now have rounded corners, borders and a frame-following shadow, drawn by the GLES, software and Vulkan renderers, with `corner_radius` and `effects` options; renderers list unsupported parts in `skipped`.
- Views are now drawn on the GPU by the GLES renderer, so live Views cost the compositor thread microseconds instead of tens to hundreds of milliseconds; Views larger than 8192 pixels per side or 32 Mpx show no picture.
- The `Camera` gains stereo and off-axis projection through new `ipd`, `fov_left`, `fov_right`, `fov_up` and `fov_down` properties, with `stereo` cameras drawing two eyes side by side in a View.
- Windows showing a DMA-BUF now fade out on close or unmap instead of vanishing, using the buffer's own contents via `Closing.source`; a fade on real GPU hardware is still pending.
- Views on the CPU rendering path now scan only the pixels where their bounds project, which speeds redraws without changing the output picture.
- `Canvas.measure` now returns width, height and ascent, the stock `Text` and `Titlebar` ellipsize long titles, canvases paint sharp at HiDPI scale, and secure canvases are masked in captures.
- Fixed the GLES renderer not drawing the cursor, which happened because the default framebuffer was left bound after reading back pixels under it.
- Popups, tooltips, combo boxes and subsurfaces from clients are now drawn on the output, following their window's transform, opacity, fading, damage, capture and `wp_alpha_modifier_v1` factor, and are hidden when the window is secure.
- `View.fps` now caps how often a View is redrawn, and `View:capture(path)` writes a PNG of a View's picture to a path inside the runtime directory and returns that path.
- Canvas nodes now paint their content, so stock shell widgets such as `Titlebar`, `Text` and `Icon` render again, with `Canvas:measure` returning real text extents and malformed `Canvas.content` writes refused as `bad-paint`.
- Reduced motion now applies to the shell's animations via `appearance.reduced-motion`, so timed changes land instantly, and the compositor plays shell timed `set` animations for the first time.
- Adds `gnoblin_render_software::render_view`, which draws a scene subtree through a camera with orthographic, perspective, or asymmetric stereo projection into an image sized to the View.
- Added a `View` node that renders a scene subtree through a `camera` (orthographic when unset) into a cached snapshot, drawn at its rect; the cache refreshes only when the source or camera changes.
- Each frame now applies queued tree transactions in order before drawing, whole or not at all, and a transaction that misses the 4 ms budget or arrives late waits for the next frame; transactions whose targets changed since their base serial are refused with `stale-base`.
- Each frame now applies queued tree transactions whole and in arrival order before drawing, deferring late or over-budget ones to the next frame, while refusing stale-base transactions as `stale-base`.
- Scene tree nodes now track an `owner` and `parented_by`, and the shell is limited to its own id range, its own nodes and a node and depth cap.
- Adds `SampledCurve` in `gnoblin-animation`, a validated list of up to 1024 evenly spaced values for custom animation easing, playable via `TweenPlayer::start_sampled` and `retarget_sampled`.

#### Session, services and recovery

- Native callbacks running past 2 s are logged and counted as strikes, and three strikes within 30 s latch the shell as degraded, so `gnoblinctl shell status` reports it and reload requests are refused while the last good generation keeps serving.
- The JavaScript and TypeScript runtime now ships as `libgnoblin-runtime-js.so` and runs inside the compositor, so `.js`, `.mjs`, `.ts` and `.mts` shells reload on file changes, keeping the running shell if an edit fails to load.

- The JavaScript shell now survives its process dying and runs a stock default config (one floating `desktop` and the stock keys) when `init.ts` is missing or fails at startup; `defineConfig` layers over it, and `gnoblinctl config reload` reloads the shell, rejecting a broken `init.ts` with `config-rejected`.
- The XR extension now survives runtime failures: a missing, refusing, lost or exiting runtime ends only the session, which is retried after 250 ms, doubling to 4 s, while `xr` seat and captures are cleaned up and the program exits only when its owner closes the socket.
- When a shell detaches or is restarted, its chord, gesture and device claims are released, except those on a seat owned by another connection, so a replacement shell can claim afresh.
- Fixed `Buses::None` dropping caller-linked agents, which stopped the keyring from starting; it now skips only the built-in D-Bus agents.
- Fixed a security hole where connections that were not the session owner could claim portal UI slots and answer secret, polkit and other prompts; these IPC methods now require the owner.
- Fixed `slot.claim` with provider `none` clearing a slot held by another connection; giving a slot back now requires `slot.release`.
- The XR extension's GPU crate now picks a swapchain format and uploads `wl_shm` Argb8888 or Xrgb8888 pictures into it through Vulkan.
- Adds the `gnoblin-lock-auth` crate providing PAM-based password checks (service `gnoblin-lock`) with a rate limiter that waits 2 seconds after three failed attempts.
- The session lock is now a compositor-owned `lock` node in the tree, exposing its `state` (`not-locked`, `pending`, `locked`) so shells attaching during a lock read `locked` and unlocking returns it to `not-locked`.
- The stock lock screen now engages on a session lock request and only disengages when `Lock:unlock(password)` receives an `ok` answer from authentication.
- A queued tree transaction whose holder detaches before it applies is now refused as `not-privileged` and changes nothing, since the holder is checked when the transaction applies rather than when it was queued.
- Gnoblin's shell now talks to its owner over a session socket, with non-blocking polling and clear link errors for refused, closed, or malformed messages instead of panics.
- The shell's tree mirror rebuilds from chunked snapshots, applies serial-checked change batches, and requests a fresh snapshot when it detects a gap or stale batch.
- The services role now starts the GeoClue agent alongside the polkit agent, following the `location` configuration table, and skips it without a system bus.
- Text printed by child processes without the `gnoblin-log` facade is logged as component `raw`; compositor, runtime and portal output is captured by default, services output needs `GNOBLIN_LOG_RAW_SERVICES=1`, and lines are scrubbed of secrets on a best-effort basis.
- The screensaver locks the session before suspend or hibernate while holding the sleep inhibitor, and on a `Lock` signal for its own logind session, and retakes the inhibitor on resume.

In a real session both are the same kind of monotonic clock and nothing changes (bead gnoblin-2ry9; `crates/gnoblin-std-impl/src/policy/focus.rs`, `crates/gnoblin-std-abi/schema/policy.toml`, `crates/gnoblin-js/tests/stock_focus.rs`, `crates/gnoblin-std-impl/tests/policy.rs`).
- The native toolkit's other delays now run on the core's clock too, as the focus policy's two already did: the arming of a not-responding alert (so Force quit), the five-second limit of a drag a window's move or resize request starts, a window frame's gestures and close fade, and a toast's fade. When the shell gives a part no `now` (or `clock`) it measured them on a monotonic clock of the toolkit's own, while the toolkit wakes it by a core timer, so a shell whose core clock is moved by hand (a `ManualClock`) woke the part at the right moment, found nothing due on its other clock and went back to sleep: Force quit never armed. In a real session both are the same kind of monotonic clock and nothing changes. One helper, `Ui::clock_ms` (over `Ui::core_now`), serves all five; a clock the shell gave still wins. The clock face of a clock canvas and the lock screen still show the system's wall time, which a monotonic clock cannot give (bead gnoblin-h9sn; `crates/gnoblin-std-impl/src/ui/update.rs`, `shell/alerts.rs`, `policy/requests.rs`, `frame/actions.rs`, `ui/toast.rs`, `policy/focus.rs`, `crates/gnoblin-std-impl/tests/shell_ui.rs`, `crates/gnoblin-js/tests/stock_ui.rs`).

#### Input, seats and accessibility

- Controller trigger, grip, face button and stick presses are now held for 150 ms so a shell drag claim can discard them instead of sending a stray `BTN_RIGHT` click, so these clicks land 150 ms later; `XRSession.chordSettleMs` is capped at 60 ms and rejects non-numeric values.
- A claimed chord now sends `chord` press and release events to the shell with the claim id, hiding both edges from the client until the claim ends, and a destroyed seat releases its claims so chords reach the client again.
- Pointer presses and motion over a window the shell rotated or moved now reach it where it is drawn, not its unrotated placement rectangle.
- On the DRM backend an absolute pointer (a virtio tablet in a virtual machine, a touch screen) now places the pointer where the device was touched. The backend took libinput's plain absolute coordinates, which are millimetres or a device's raw axis units, for fractions of the device's range, so every point was clamped into the output's bottom-right corner and no client was ever under the pointer, with no `wl_pointer.enter`; touch points had the same fault (lane Drm7xyb, bead gnoblin-7xyb; `crates/gnoblin-backend-drm/src/libinput/mod.rs`). The CI VM job now sends a tablet move, a click and two keys through QMP and checks what `wev` receives (`scripts/ci/vm/input-check.sh`).

#### Outputs and backends

- Mode changes on hardware outputs are refused unless the `GNOBLIN_DRM_MODESET=1` environment variable is set for the session, since DRM modesetting is untested on real hardware and can blank the display; scale-only changes still work.
- Passing `primary` to `output.apply` is now refused with an error instead of being silently ignored, since the layout derives the primary output.
- The hardware backend now lights the display. Its first frame, and the first after a staged mode change, was queued as a plain page flip, which the kernel refuses with `EINVAL` while the output still needs a modeset, so every frame was refused and the screen stayed off. Such a frame is now committed with the modeset.
- The hardware backend no longer shows the desktop upside down. A frame was drawn into the scan-out buffer with the renderer's own row order, whose first row is the bottom of the picture, while the display scans a buffer's first memory row out as the top line. The renderer now composes into its own target, which also keeps the frame's damage, and copies it into the buffer with the rows reversed.

#### Session, services and recovery

- The session lock card's takeover timing is now measured and documented: in release builds it takes the password about 3.1 s after the shell's last healthy beat and about 1.1 s after the keyboard leaves the lock screen, matching the documented "3 seconds" and "1 second" plus half a second.
- The session clock, which idle, rest focus and the lock screen's lease read, no longer runs slow while the loop turns more often than once a millisecond: each turn dropped the sub-millisecond rest of its time, so the lock screen's 2 s lease and 1 s grace took about 3.2 s of the wall clock while keys were typed. The rest now carries to the next turn (`TurnClock` in `gnoblin-wayland`), and the card takes the password about 0.15 s earlier.
- Fixed a session that was stopped while its loop was still starting never ending. calloop's `EventLoop::run` clears its stop flag as it begins, so a `ControlHandle::stop` that arrived just before it was forgotten, the loop ran for ever and whoever joined the session waited with it. `gnoblin-wayland` now keeps the request itself (`Server::run` ends before its first turn when a stop was already asked for), and the stop wakes a waiting loop at once instead of at the next 100 ms timeout. It hung `gnoblin-wlcs` `two_touch_devices_get_different_slots` in the scheduled test matrix for hours, and made `Session::drop` of the compositor's `eis` tests wait for minutes.
- Fixed a JavaScript shell reload leaving most keys dead: the new generation keeps its seat claims until takeover, and the swap releases the old claims first, so `Super+1` to `Super+9`, media keys and the three-finger swipe keep working.
- Fixed a click's focus change being lost when the seat changed mid-transaction; refused writes are now resent, up to `STALE_RETRIES` times in a row.
- Session lock password checks now answer `denied` for wrong passwords, `rate-limited` after three failures, and `failed` when the check cannot run, keeping the session locked and logging a single warning without the password.
- After a shell restart, windows are placed again and stay mapped, keeping their client size.
- Fixes a bug where an attaching shell received the compositor's seat and screen node changes twice, once in the attach snapshot and again as `changes` events.
- A gnoblin started by a systemd service whose stderr was then redirected (a test harness, a CI runner, a wrapper that pipes the log) now prints its log on stderr. It trusted an inherited `JOURNAL_STREAM` as proof that stderr was the journal and sent every line there, so a refusal at start showed nothing on stderr. The variable now counts only when its device and inode are stderr's own, as systemd documents.
- A shell instance that starts after another ended no longer hears what the ended one's connections had queued. `reset_session` left the events no generation had dispatched in the queue, so the next shell's first turn delivered them: a dialog request of the old slot connection reached the new shell's listeners and was answered `pass` on the new connection. The `services` tests of `gnoblin-core-impl` failed whenever a test that offered a request ran before one that listened for requests. The reset now drops those events (`GenerationHost::discard_events`; lane SvcIdle).

#### Configuration

- The settings a Rust or a Python shell writes to the devices and to the compositor (`gnoblin.compositor.user_shaders`, `Keyboard.repeat_delay`, `Mouse.sensitivity` and the rest) now reach the compositor and apply from the next login, as a TypeScript shell's do. Before, nothing committed them: the write stayed in the shell's ledger and only the JavaScript runtime sent it. The core's shell host now commits what the shell wrote over the document the compositor holds, after the turn that wrote it and with no call of the shell's own; a shell that writes nothing changes nothing, a reload that stops writing a setting takes it back, and a TypeScript shell commits as before. A Python or native shell that is itself `~/.config/gnoblin/shell.py` or `shell.so` now has the last accepted document kept for it, as the compositor already kept it for `shell.ts` (lane C7by, bead gnoblin-c7by; `crates/gnoblin-core-impl/src/document.rs`, `crates/gnoblin-config/src/{locate,patch}.rs`, `crates/gnoblin/tests/modular/native_settings.rs`, `docs/rust-shell.md`, `docs/python-shell.md`, `docs/custom-shaders.md`).
- A real reload now clears the shadows and borders a window's earlier script styled, instead of leaving them on the window.
- Errors thrown inside the stock library now report the correct `.ts` file and line, and its types are stripped once per process instead of once per generation.
- The JavaScript shell's time limits are relaxed: module loads may take up to 30 s (was 5 s), listener calls up to 1 s (was 100 ms) and frames up to 5 s (was 500 ms), and loading the default config now uses the module-load limit.
- Fixed a bug where re-enabling decorations during a config reload could place the titlebar above the screen without moving window content down.

#### Portals, capture and privacy

- Fixed a flaky portal test where dialog keys could arrive before the compositor opened the dialog, leaving it open indefinitely; keys are now sent only after the compositor acknowledges the offer.
- Fixed a security issue where any D-Bus client could make the GeoClue agent show a location prompt; now only the connection owning `org.freedesktop.GeoClue2` is answered, and other senders get `org.freedesktop.DBus.Error.AccessDenied`.
- Fixed a security issue where View captures showed pixels of secure windows; captures now mask them grey, controlled by `capture.secure-treatment`.
- Fixed a security issue where content below a secure node could escape redaction in View captures and screen capture; such nodes are now masked consistently across all capture paths.
- Fixed a security issue where a screen capture requested right after a `secure` mark was acknowledged could still include pixels from the secure window for one more frame.
- Secure window content in Views is now masked in every capture, on-screen display and renderer path, including while the session is locked.
- Fixed a security issue where a PipeWire screen-capture consumer could receive a buffer captured before a `secure` mark, because the last filled buffer was held in the daemon across the mark.
- View captures now copy the requested region and honour the buffer's `wl_shm` format, while buffers of an unoffered format or too small are refused with a `failed` event.
- Windows the shell marks `secure` are now masked in screen capture, including marks written from a stock-shell rule or a user shell file, and clearing the mark unmasks them.
- The portal backend now destroys the ScreenCast consent dialog and its hidden parent window when a screen cast session ends, instead of keeping them alive.
- A shell process could answer prompts or authorization requests it never received through `prompt.respond`, `prompt.cancel`, `auth.*` and `location.authorize_app`, because the recipient check was skipped; the compositor now enforces it.

#### Client protocols and compatibility

- Shells built before the shader fields were added keep working after upgrading, without needing a rebuild, because the effect array's stride now comes from each shell's own `GnoblinEffect` record size.
- The wlcs test descriptor now lists the `zwp_tablet_manager_v2` global, matching what clients see in the registry once tablets are served.
- Fixed `wl_subsurface.set_position` to apply with the parent's commit, and attaching a buffer to an unconfigured `xdg_surface` now raises `xdg_surface.unconfigured_buffer` immediately.
- Fixed a race where the JavaScript shell could read stale values of `decoration`, `focused` and window size, so the stock titlebar was sometimes not mounted for a window.
- Fixes the `xr` seat being created on the first frame and listed in attach snapshots, `gnoblin_view_source_manager_v1.create_source` accepting 64-bit node ids and current scene state, and stock shell chords like `<Super>Left` and `<Super>space` now parsing so their bindings work.
- The XR frame loop now runs frames as soon as the session begins in `Ready`, not only after `Synchronized`, `Visible` or `Focused`, so Monado clients get frames.
- Seat and node `claim` and `unclaim` calls from the shell are now captured in operation order instead of being refused as unknown methods.
- A callback added with `Operation:on_complete` after the operation had finished now runs, instead of the runtime calling the Operation table and logging an error.

#### Command line and tooling

- `GNOBLIN_LOG=wayland:debug,*:warn`, the component syntax `docs/guides/logging.md` documents, is now accepted by every process and sets the level of each component. It was refused as an invalid `EnvFilter` directive, and the debug lines of the compositor's own components could not be turned on. A value in `tracing`'s syntax (`smithay=debug,warn`) still works (lane Drm7xyb, bead gnoblin-yv6i; `crates/gnoblin-log/src/init.rs`).
- `cargo xtask deps` passes its own test again, now correctly asserting that `gnoblin-std-portal` is refused access to egui.
- `just core-only` passes again: it refused the core because `gnoblin-std-abi` appeared in its build tree. That crate is reached only at build time, through `gnoblin-sdkgen` rendering the core's `gnoblin.model` catalog, and is never linked. The rule now refuses any std crate the core links, and any std crate its build reaches other than that one, by that one path.

#### Packaging and install

- The `s3` back end of `pkgrepo publish` no longer uses `aws s3 sync`, which uploaded and then deleted every arch package that has a `.sig` beside it in one nightly run. It now lists the bucket once, uploads what the manifest or the listing shows has changed, and deletes keys that are not in the tree only after every upload.

#### Documentation and tests

- The docs-parity gate now reads the native library's declarations alone, where it read them joined with the TypeScript library's; a page that documents a name only the TypeScript library has (`gnoblin.clients.onAdded(handler)`) now fails it (Beads `gnoblin-mti1`; `xtask/src/docs_parity.rs`). No page documents one: 344 documented names are all on the native surface.
- Fixes CI gate failures: a duplicate test-only `View` type is renamed `EngineLink`, `ext-clippy` and `ext-test` now pass under `--locked`, `_gnoblin_core.pyi` declares `verb_call` and `verb_subscribe`, chord claims match in both `<Super>Tab` and `Super+Tab` spellings, and several racy tests are now deterministic.
- Script API values that nothing applies, such as `vrr`, `Camera2D` and `Camera3D` transforms, `Viewport.clearColor`, `background`, `filter` and inset shadows, are now documented as "Not applied yet" and each has a recorded reason.
- Fixed flaky `gnoblin-js` tests that assumed a fast machine by making the shell's script clock injectable via `JsShellConfig::clock`, so timing-sensitive tests use a manual clock and honest scripts get a 5 s budget.
- Shell key routing is now tested end to end: a shell node with `input` holding the seat's focus receives keys sent over EI as `tree.event` key events, and no key reaches it once the session is locked.
- Adds a deterministic test for the portal's IPC thread deferral, confirming consent offers are served before a deadline and that queued graph events and dialog answers are applied in the order they were read.
- Fixes the EIS real-client pointer tests so they target the window's drawn rectangle rather than its configured geometry, so pointer events land on the surface again.
- Flaky shell VM tests now wait for the state they assert instead of fixed frame counts or the shell's `placed` flag before reading results.
- Fixed the `gnoblin` process suites failing with `Text file busy` when they ran a copy of the binary they had just made.
