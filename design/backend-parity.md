# Backend parity audit: headless, nested and DRM

**Status:** audit, the fixes, backend selection in the shipped binary, the hardware backend wired, and a conformance suite
that holds the status table to the code. Items marked [INFERENCE] were read from source and not run. The Backend trait is
`crates/gnoblin-backend/src/lib.rs`, headless is `src/headless.rs`, nested is `src/nested/`, DRM is
`crates/gnoblin-backend-drm/src/lib.rs`. The tables describe the state before this lane; the last table says what
landed.

## What "the same" means here

The compositor above the `Backend` trait must behave identically on every backend wherever the host protocol or the
hardware can carry the behaviour. What a backend physically cannot do is refused with the typed `BackendError`
vocabulary (`Unsupported`, `Unpresentable`, `ModesetDisabled`), never ignored and never faked. A nested session does
not emulate gamma, power or arbitrary modes: a wlr-gamma-control forward would tint the host's whole monitor, not the
window. Headless is a virtual display and records gamma and power as virtual hardware, which is the one deliberate
asymmetry; the conformance suite states it per backend.

### What the words mean

- **supported** is a thing the backend does. **refused** is a thing it declines on purpose, always with the typed
  answer `BackendError::Unsupported` (or the more specific `ModesetDisabled`, `Unpresentable`): never silently, never
  emulated. A nested session does not fake gamma or power, because a host monitor's table and power state are shared
  by every window on it. **n/a** is a capability that cannot exist for that kind of backend: a window has no DRM
  master, a virtual display has no host.
- **fake kernel** (DRM cells) means the decision above the ioctl is proven against a recorder that stands in for the
  kernel (`crates/gnoblin-backend-drm/src/conformance.rs`). **unproven on hardware** means only a real GPU, seat and
  display can prove it, and it has not been run on one: the owner-run checks are in
  `docs/real-hardware-verification.md`.

Tolerances: pixels from the software renderer must be **equal** at every probe (a solid rectangle on whole pixels has
nothing to anti-alias); a GPU renderer may differ by at most 2 per channel (a float colour rounded to eight bits
twice). Nested is hosted by this repository's own compositor, which is a real Wayland compositor, so what is proven is
the nested backend against the protocol and against one implementation of it. A different host (Sway, Mutter) is a
second implementation of the same protocols, and nothing here proves it: the conformance suite does not run against
one (see "What landed, and what did not").

## Findings that decide the work

1. The `gnoblin` binary never selects a backend. `SessionConfig::default()` is headless and no config leaf, flag or
   variable changes it (`crates/gnoblin/src/main.rs:159`, `role.rs:56`). Only tests choose nested.
2. `Backend::build` refuses every renderer but `auto`/`software` for nested (`compositor/src/backend.rs:156`) and refuses
   `Drm` outright with a static string (`backend.rs:166`). The compositor crate does not depend on `gnoblin-backend-drm`.
3. Nested keeps a `Software` field instead of `AnyRenderer` (`nested/surface.rs`), so GLES and Vulkan cannot be
   created there, and every GPU-facing trait method falls to its permissive default.
4. `BackendEvent::Disconnected` is documented as "the session must end" but the server loop only recomputes the layout
   (`wayland/src/server.rs:1703`): a nested session whose host died, or whose last window was closed, runs forever with
   no output.
5. The Drm struct reports `target() == None` and `capture() == None` (`drm/src/lib.rs:452,525`): it is scan-out only.

## Auto selection

`auto` takes the first rule that holds: a reachable host Wayland socket (`compositor.nested-display`, else
`WAYLAND_DISPLAY`) is `nested`, because a running compositor owns the seat; a seat (`XDG_SEAT` or `SEATD_SOCK`) with a
`/dev/dri/card*` node is `drm`, which is how the legacy session started on hardware; otherwise `headless`. `DISPLAY`
alone selects nothing, because the nested backend is a Wayland client. `auto` never falls back after a start fails, and
an explicit value is never second-guessed. The rule is `crates/gnoblin-compositor/src/backend_select.rs`, a pure function
with a test per line.
