# Accessibility status

Status of each accessibility area on branch `rust-compositor`, checked against the code. It is a
snapshot, not a roadmap. Each row names the code or test that supports it. Where a claim could
not be checked by a test, the row says so.

Citations are `path:line` or a test name. `[INFERENCE]` marks a claim not checked against code.

Status values:

- **done**: implemented and a test in this tree exercises the behaviour.
- **partial**: some of the path exists, but a link is missing or no test covers the behaviour.
- **absent**: no code.
- **needs real AT**: the behaviour depends on a real assistive technology, which no test here runs.

## Next steps

- Wire `A11y::apply` into the live key path, or remove the sticky, slow, bounce and mouse-key
  claims from the docs. A test must show a key through the real path.
- Start the keyboard monitor service, or remove its claim.
- Add a capture test with the magnifier on, and a test that the visual bell flash is drawn.
- Fix the schema zoom maximum (32 in the schema against 16 in the compositor).
- Add a real-AT check for the screen reader before any claim about it.
