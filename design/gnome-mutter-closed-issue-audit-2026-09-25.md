# GNOME and Mutter issue audit

Reviewed 25 September 2026. This is a first-pass audit of closed input,
accessibility, and desktop-behavior reports in Mutter and GNOME Shell. It
records what the tracker actually says, whether another desktop documents the
behavior, and whether Gnoblin has a concrete implementation opportunity. A
closed status by itself is not evidence that a report was dismissed without
reason.

## Search scope and next pass

The first pass queried closed issues in Mutter and GNOME Shell for touchpad,
scroll speed, pointer acceleration, magnification, clipboard, gestures, focus,
and window interaction. It inspected issue descriptions, closure notes,
duplicate targets, relevant merge-request states, and KDE documentation. It
did not review every closed issue in either tracker, nor inspect every GNOME
component or distribution bug tracker.

The best Gnoblin follow-ups from this pass are:

1. Finish and merge custom pointer curves for mouse and touchpad pointer
   motion.
2. Maintain Gnoblin's configurable touchpad scroll speed and compare its
   actual runtime behavior with the open Mutter implementation.
3. Watch the magnifier scroll MRs; only start a Gnoblin implementation if the
   upstream work becomes inactive or fails to deliver the documented behavior.
4. Treat clipboard history as a product/security design question and build on
   explicit user consent if Gnoblin implements it.

The strongest verified KDE differences in this pass are touchpad scroll-speed
control and modifier-scroll magnification. Clipboard history is also a shipped
Plasma capability, but its Wayland security model is materially different
from the unmanaged protocol Mutter rejected.
