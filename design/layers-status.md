# Layers: status and gaps

Status of `design/layers.md`, checked against the code on `rust-compositor` at `6ce209796`. Every claim cites `file:line` or a test name. Lines are from that commit and drift as code moves. `[INFERENCE]` marks a claim that was not run or not read in full.

## Answer: do window frames use layers?

No. The window frame path bypasses the layer model.

- `crates/gnoblin-wayland/src/protocols/gnoblin_window_frame_v1.rs` never calls the registry. The file has no `register`, `LayerRegistry`, `gnoblin_layers` or `LayerProvider` reference.
- Ordering and hit testing use the old structures. `frame_window_at` (`:640`) walks `self.wm.stack()` and looks up `self.frame_tables.frames` (`:644-649`). The layer registry is not consulted.
- Frames are not painted at all. `frame_surface_committed` (`:790`) stores the committed regions and presented flag. Those are read only by the `window_frame()` snapshot (`:516`) and by `frame_window_at`. No code draws the frame surface. `crates/gnoblin-backend/src/render/compose.rs` and `crates/gnoblin-render-frame` never reference the window-frame protocol or `frame_tables`. The header comment at `gnoblin_window_frame_v1.rs:76-80` says the frame is configured with zero extents and is not composed yet.
- Only the window's own surface is drawn. `State::sync_content` (`state.rs:1857`) calls `composer.set_window_content` (`state.rs:1862`) for the window's content, not for its frame.
- `gnoblin.window_frame` does not exist as a layer: no `register_layer` call names it (`grep -rn "window_frame" crates --include=*.rs` returns the protocol, its tests and `state.rs` lifecycle hooks only). `design/layers.md:204-215` describes it as a layer with paint and input areas. Neither exists today.

What the lifecycle hooks do: `refresh_window_frame` (`:671`, called from `state.rs:1847`) creates or refreshes the entry (insert at `:774`); `close_window_frame` (`:778`, called from `state.rs:1758`) removes it; `frame_pointer` (`:533`, called from `state.rs:1572`, `:3265`, `:3280`) routes pointer input to the frame's regions.

Suspected bug (needs a test, not yet written): `frame_window_at` uses `?` at `:649` on the frame table lookup. Any visible stacked window with no frame entry returns `None` for the whole search. Most windows have no frame, so a frameless window above a framed window hides the framed window's titlebar outside the top window. Expected: the search continues past a window with no frame. Test to add: `a_frameless_window_above_a_framed_window_does_not_hide_its_frame`, beside `a_pointer_over_overlapping_windows_reaches_the_topmost_frame` (`crates/gnoblin-wayland/tests/window_frame.rs:551`).

Existing frame tests (all in `crates/gnoblin-wayland/tests/window_frame.rs`): `a_mapped_window_is_offered_a_frame_and_presents_it` (`:289`), `a_buffer_of_the_wrong_size_is_a_protocol_error` (`:401`), `a_pointer_over_overlapping_windows_reaches_the_topmost_frame` (`:551`), `a_pointer_over_a_tiled_window_reaches_its_own_frame` (`:610`), a renderer-crash test (`:667`), and a closed-window test (`:690`). None of them checks a painted pixel, because nothing paints the frame.

## Ranked gaps (user impact first)

1. **Window frames are never drawn.** `compose.rs` and the backend do not reference frame surfaces. A frame-drawing client (the only way to get a frame today) is hit-tested but invisible. Largest user-visible gap.
2. **Frame hit testing hides framed windows** (`gnoblin_window_frame_v1.rs:649`, `?`). Pointer over a frame can go to the wrong window whenever any frameless window is above it.
3. **Frames are not layers.** No `gnoblin.window_frame` record, no registry ordering, no input areas from the registry. Blocks the design's paint/input split (`layers.md:204-215`).
4. **Popups have no defined draw path in the compositor.** `compose` draws only the root `set_window_content` (`state.rs:1862`). Popups go through `xdg_shell.rs:176` `popup_committed` and `wl_compositor.rs:94-95`, and nothing shows them drawn above their root in compose. [INFERENCE: not traced end to end; test needed: a menu popup above its parent is visible in a capture.]
5. **Modal input policies `Passive` and `Grab` are refused** (`state.rs:2484-2489`). Any portal or dialog asking for them is dropped with a warning.
6. **Capture secure masking parity.** Headless and nested route through `capture_redacted`. The x11 backend has no secure path found. No DRM backend exists in this tree, so the design's DRM readback has nothing to cover [INFERENCE: confirm the design still means DRM].
7. **`layers.list` IPC is absent.** Only `register` exists (`layers.toml:22-23`). The parity test and clients cannot read records. Design says `layers.list` is the one list for everything.
8. **`parent_window` for `wayland:` handles** is only half wired. Lookup exists (`ipc/server.rs:900`); portal consumption is untraced [INFERENCE].
9. **`window_menu` is not a shipped extension.** The core request path exists (`state.rs:2324`) but nothing draws a menu for it.
10. **`gnoblin.alerts` absent.** Design phase 8.
11. **Lua `gnoblin.layers` absent** (phase 10). Blocked on D22. Phase 9's config `layers` section is also missing.

## Phased plan (lane-sized, tests first)

Each slice writes its failure-mode test first, then the code, and pushes green on its own. Gates per the lane rules (`check`, `clippy -D warnings`, `fmt`, `test` for touched crates, `xtask dupes/logging/deps/layout/docs-parity`).

- **Slice A, frame hit test (small, bug).** Replace the `?` at `gnoblin_window_frame_v1.rs:649` with a skip. Test: `a_frameless_window_above_a_framed_window_does_not_hide_its_frame` in `crates/gnoblin-wayland/tests/window_frame.rs`. Accept: the pointer over the framed window's titlebar outside the top window reaches its frame.
- **Slice B, register frames as layers.** Register `gnoblin.window_frame:<id>` as a window-scope entry above its target with `Wm::register_layer`, following the design's built-in rule. Test: frame of a window below a raised window follows the stack (fails today). Accept: `layers.list`-style record exists (after slice G), stack follows.
- **Slice C, draw frames.** Compose the frame surface above the window content in `compose.rs`, ordered by the frame list. Test: a capture shows the frame's pixels around the window; a frame does not paint over a `top` bar. Accept: pixels appear in `headless` capture.
- **Slice D, frame input areas.** Move pointer lookup for frames from `frame_tables` to the registry input areas, so CSD drag areas still move the window (`layers.md:544`). Test: drag over a CSD titlebar moves the window while the frame paints over it.
- **Slice E, popups.** Define the popup draw path above the root record, ending with the root. Test: a popup above its parent is visible in capture and gone when the parent closes. Accept: no popup record in `layers.list`.
- **Slice F, input policies.** Implement `Passive` and `Grab` in `set_modal` (`state.rs:2484`) or drop them from the schema. Test per policy. Decision needed: whether `Grab` may exist for portals at all (design is silent).
- **Slice G, `layers.list`.** Add `list` to `layers.toml` and dispatch in `ipc/server.rs:1565`. Test: `crates/gnoblin-compositor/tests/layers.rs` lists built-in records with `provider`, `scope`, `band`, `state`. Accept: parity assertion `gnoblin.surface_layer_shell:osd` resolves through the list.
- **Slice H, secure capture parity.** Add the secure path to the x11 backend capture. Test: a secure node never appears in a capture on each backend that exists. Decision: DRM is absent from this tree; drop it from the design or add a backend.
- **Slice I, `wayland:` parent.** Wire `exported_window` into the portal parent check (`portal.rs:376` neighbour). Test: a dialog with a valid `wayland:<handle>` parent is typed, an unknown handle is refused. Remove the stale "no caller exists yet" comment (`server.rs:919-920`).
- **Slice J, window menu.** Ship `gnoblin.window_menu` as an extension, enabled by default, using `request_menu` (`state.rs:2324`). Test: a menu request for a live window produces a menu record; for a closed window it is dropped (existing `request_window_menu` behaviour).
- **Slice K, alerts.** Implement `gnoblin.alerts` and its content provider. Test: alert record ordering in `windows`/`overlay` per design.
- **Slice L, Lua and config.** After D22 per-extension environments: `gnoblin.layers.register`, `[powers.layers]`, the `layers` config section. Blocked until D22 is decided.
