# Patches squash plan (option B)

Fold fixup, revert, split and rewrite chains into the patch they repair, so that each patch is one coherent change. Every
fold keeps the final patched tree byte-identical. This plan comes first; the result and the evidence follow at the end.

## Method

1. Baseline: reset a scratch clone to the upstream tag, copy the overlays as `cmake/source-step.cmake` does, `git am`
   the series, record `git rev-parse HEAD^{tree}`.
2. Find fixups with `git blame` on the lines each patch deletes (a patch that mostly rewrites lines of one earlier patch
   is a fixup of it) and by reading the small patches next to a larger one in the same file.
3. Per topic: `git rebase -i` the scratch stack so the fixups sit under their target as `squash`, write the combined
   message, export the target patch, delete the folded files, `renumber`, then require the same tree hash and
   `manage-patches.py check`. One topic is one commit.
4. A patch that is only a hook for an overlay, a version floor or a separate setting stays alone, even when it edits the
   same file as its neighbour. Only a fixup of, revert of, split of or rewrite of the same hunks is folded.

Paths below are the series paths before this branch (`NN-topic/NNNN`); numbers shift after each renumber.

No exception: every fold left the tree hash unchanged, so no patch changed the generated tree and no `config.h` proof is
needed. Each fold rewrote only the target patch that holds it; no downstream patch had to be regenerated. `design/patches-layout-mapping.tsv` maps each old path to the patch that now holds its change. Tests that
named a folded patch (`focus-policy-contract`, `native-socket-text-snap-api`, `session-lock-protocol`,
`csd-pixel-lifetime`) read the surviving patch. The evidence is in `~/.cache/plt/evidence/squash-*`.
