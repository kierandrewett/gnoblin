# Running `.ts` directly in embedded QuickJS (Rust) — research report

Date of facts: 2026-11-13. "Verified" = read from the cited primary source today; "unverified" = not confirmed; "[INFERENCE]" = my reasoning.
No cargo on this machine, so nothing below was built or benchmarked by me.

## 0. Findings that change the question

1. **TypeScript 7.0 (2026-07-08) is a native Go binary and ships no programmatic API.** `tsc.js` no longer exists in 7.x. The last JS-codebase compiler is TypeScript 6.0 (npm `@typescript/typescript6`, command `tsc6`). Source: https://howtodoinjava.com/typescript/typescript-7-native-compiler/ and https://github.com/microsoft/typescript-go (README: "This Repo Is Closed", "API: not ready"). **Embedding the real compiler in QuickJS (tsk) is therefore frozen at TS <= 6.0 and has no future.** Type checking must shell out to an external `tsc`.
2. **A QuickJS fork with native TS syntax does exist**: `dquickts` (see 1.2). It is not called `quickjs-typescript`.
3. **The workspace MSRV already equals oxc's**: `/home/kieran/dev/gnoblin-rust-wt/Cargo.toml` has `rust-version = "1.97.0"`, `edition = "2024"`, toolchain 1.99.1. oxc 0.158.0 declares MSRV 1.97.0 (crates.io). Adding oxc does not raise the measured MSRV today.
4. **A schema-to-artifact generator pattern already exists**: `crates/gnoblin-lua` generates `gnoblin.d.lua` from `gnoblin-schema`; `crates/gnoblinctl/src/generate.rs` renders from the schema into `OUT_DIR`, nothing committed. `gnoblin.d.ts` should be one more output of the same catalog.

**Decision between oxc, swc and dquickts**

- oxc: best Rust API fit (arena AST, one-pass transformer, codegen + map, MSRV already matched, MIT, used by Rolldown per the oxc post). Cost: breaking 0.x API; partial namespaces; legacy-only decorators documented.
- swc: viable fallback, heavier, slower, Mark/GLOBALS ceremony.
- strip-only (swc_fast_ts_strip / amaro approach): attractive because **positions are preserved so no source map is needed**, but drops enums/namespaces/param properties — a "run `.ts` directly" promise that fails on `enum` is poor UX; crate is stale.
- dquickts: best raw UX (zero pass, exact lines, enums/decorators/`using` natively), worst coupling (single fork, vendored rquickjs port, rebase burden, unknown licence terms).

## 3. Real TypeScript compiler inside QuickJS (`alejandroliu/tsk`)

Verified from https://github.com/alejandroliu/tsk README:

- Runs **TypeScript 5.4.5 `tsc.js`** under `qjs --std -I node_shim.js ...`. Created 2026-05-20, 4 commits, 0 stars, MIT. Needs a Node shim (`fs`, `path`, `os`, `buffer`, `process`, `crypto` SHA-256, CJS `require`).
- Limitations stated: no `--watch`, no `source-map-support`, no CPU profile. **No performance numbers published.**
- Cost [INFERENCE, unmeasured]: parses the multi-MB tsc bundle and lib.d.ts on every invocation in an interpreter with no JIT; expect seconds for a trivial config, versus 3.0 s for the _native_ TS 7.0.2 on a 1,001-module / 183k-line project (2 vCPU; https://howtodoinjava.com/typescript/typescript-7-native-compiler/ — third-party measurement).
- Dead end: no TS >= 7 JS bundle; no programmatic API in 7.0 ("`createProgram`... TypeScript 7.0 ships no programmatic API"). Also the compiler would sit inside the privileged runtime process (spec s18 says the runtime is a restartable client with CPU/memory budgets).

**Verdict: do not embed a type checker.** `gnoblinctl check` spawns an external `tsc` (7.x, native) or `tsc6`/`tsgo`.

## 4. Source maps so runtime errors show the `.ts` line

Facts: QuickJS records line+column in debug info since 2025-04-26 (changelog). Module names we choose appear in `error.stack` frames. oxc returns a map per file (`CodegenReturn.map`). `oxc_sourcemap::SourceMap` (10.0.0, BSD-3, verified) has `from_json_string`, `generate_lookup_table()`, `lookup_token(table, line, col)`, `lookup_token_approx(...)`, `compose(...)`.

Plan:

1. **Module name = absolute path of the `.ts` file** (`/home/u/.config/gnoblin/init.ts`), never a hash name, so frames and `import.meta.url` are meaningful.
2. Per-generation `HashMap<ModuleName, Arc<SourceMapEntry{lookup_table, map}>>` filled by the loader.
3. **Remap in the host**, not in JS: on uncaught exception/unhandled rejection/handler error, take `stack` (string) and rewrite each `at fn (path:L:C)` frame through the lookup table (0-based in the lib, 1-based in QuickJS: convert). Show `file.ts:L:C` plus a source snippet from the original text (we have it, it is hashed already). Used by: journal log, `gnoblinctl check`, reload-failure report (spec s18 step 5: "Report module path, line, object, field").
4. Expose `gnoblin.debug.mapStack(err)` for user `catch`+log.
5. **Gap**: user-visible `err.stack` read inside JS is unmapped on upstream QuickJS/rquickjs (no `Error.prepareStackTrace` there — unverified for rquickjs 0.14). dquickts does not have this problem (native positions; and ports the V8 stack-trace API). If user-level stacks matter, either wrap `Error` capture in the prelude, or run the codegen in a mode with matching lines (not available in oxc — unverified).
6. Syntax and semantic parse errors are reported by oxc in `.ts` coordinates, before QuickJS ever sees the file — best case.
7. Do NOT also embed `//# sourceMappingURL`; keep maps out-of-band to avoid QuickJS strip/size issues.

## 5. Module imports of `.ts` and the bare specifier `gnoblin`

rquickjs 0.14 (MIT, MSRV 1.87, `loader` feature) exposes `Loader::load(&mut self, ctx, name, attributes: Option<ImportAttributes>) -> Result<Module>` (verified) and a `Resolver` trait (name only verified; check signature in spike), `BuiltinLoader`/`ModuleLoader`/`FileResolver`/`NativeLoader`, and tuple composition of loaders. Use one custom resolver + one custom loader:

| Specifier                                | Resolution                                                                                                                                                                                                                                                                                                                |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `"gnoblin"`, `"gnoblin/<module>"`        | Resolved to internal name `gnoblin:<module>` (never to a file). Loader serves **embedded** JS facade modules (compile-in with `include_str!`; plain `.js`, no transform) that re-export from a native `ModuleLoader` module defining classes/functions. Unknown submodule -> error listing valid ones.                    |
| `"gnoblin/extensions/<id>"`              | Resolved by the extension manager (spec s17); absent extension -> clear error, not a file lookup.                                                                                                                                                                                                                         |
| `./x`, `../x`, `/abs`                    | Join with importer's dir; try in order: exact; if `.js/.mjs` missing then `.ts/.mts` (what `dquickts` and TS bundler resolution do); extensionless -> `.ts`, `.js`, `/index.ts`, `/index.js`; explicit `./x.ts` allowed (`allowImportingTsExtensions`). `canonicalize()` and key the module by canonical path for dedupe. |
| `x.json` with `{type:"json"}`            | Upstream QuickJS 2025-09 has JSON modules/import attributes; allow only under config roots.                                                                                                                                                                                                                               |
| `.tsx`, `.cts`, `node:*`, npm bare names | Reject with a readable error (spec: no Node/npm).                                                                                                                                                                                                                                                                         |

Sandbox (spec s3): confine file imports to allow-listed roots (`~/.config/gnoblin/`, `$XDG_DATA_HOME/gnoblin/`); reject any canonical path outside, including via symlink. Do not use `oxc_resolver` initially (it brings tsconfig `paths`/extension-alias logic we would then have to sandbox; README confirms tsconfig `paths` support, extension-alias unverified); revisit if users want tsconfig `paths`.

Loader for `.ts/.mts`: read bytes -> hash -> compile (s6) -> `Module::declare(ctx, canonical_name, js)`. `.js/.mjs`: pass through. Hot reload (spec s18): each runtime generation has a fresh `Runtime`, but the **hash-keyed compile cache is shared across generations**, so an edit to one file recompiles one file.

## 6. Recommended pipeline

```
resolve(specifier, importer) -> canonical path
read bytes -> key = blake3(bytes ++ OXC_PIN ++ options_digest)
cache hit?  -> (js, map)          // in-memory Arc cache shared by generations; optional disk copy
miss:
  1 parse     Parser::new(&alloc, &src, SourceType::from_path(path)?).parse()   // errors -> miette-style, .ts coords
  2 semantic  SemanticBuilder::new().with_enum_eval(true).with_excess_capacity(2.0).build(&program)
  3 strip     Transformer::new(&alloc, path, &opts).build_with_scoping(scoping, &mut program)
                opts = TransformOptions::from_target("es2023") (QuickJS-supported level; verify exact accepted string)
                typescript.only_remove_type_imports = false (friendly: no `import type` needed)
                typescript.rewrite_import_extensions = None (our resolver handles .ts)
                typescript.optimize_const_enums = true; allow_namespaces = true
                decorators: off unless the spike shows spec use (legacy only)
  4 emit      Codegen::new().with_options(CodegenOptions{ source_map_path: Some(path), ..default }).build(&program)
              -> code, map (oxc_sourcemap::SourceMap)
  5 store     { js, map.to_json_string() } under key; build lookup table lazily on first error
Module::declare(ctx, canonical_path, js)
error path: host remaps stack frames with the lookup table (s4)
```

Cache notes (be honest about value): transform costs ~1 ms per 1000 lines [INFERENCE from the vendor figure], so the cache is **not** a startup optimisation. Its value is (a) not recompiling unchanged modules on reload, (b) keeping maps available for diagnostics after a file changes on disk (the stack of an old generation can still be mapped). In-memory is enough; a disk cache under `$XDG_CACHE_HOME/gnoblin/ts/<hash>.{js,map}` is optional and key MUST include oxc version and the options digest. Do not cache QuickJS bytecode (tied to engine build).

Behavioural contract to document: TypeScript is **isolated-modules** semantics; no type-directed emit; `const enum` values are inlined within a file only; types are never checked at runtime.

## 7. Shipping `.d.ts` and `gnoblinctl check`

**Generation:** add a `gnoblin.d.ts` renderer next to the existing generators (`gnoblin-config-codegen` / `gnoblinctl/src/generate.rs`: schema -> `OUT_DIR`, uncommitted). Output = generated object/property/event declarations + hand-written `data/js/types/*.d.ts` (listener interfaces, helper types), installed to `$datadir/gnoblin/types/`. Form: a global script declaration (`declare const gnoblin: Gnoblin;`) plus `declare module "gnoblin" { ... }`, `declare module "gnoblin/<mod>"`, `declare module "gnoblin/extensions/<id>"` blocks. Version stamped; a unit test asserts the schema version equals the d.ts header (same refusal logic as `generate.rs`).

**No-build editor setup:** TypeScript 6/7 default `types` is empty, so `@types` discovery cannot supply the global; use `files`/`include`:

- Ship `$datadir/gnoblin/types/tsconfig.base.json`: `compilerOptions { target: "es2023", lib: ["es2023"], module: "esnext", moduleResolution: "bundler", strict: true, noEmit: true, isolatedModules: true, allowImportingTsExtensions: true, types: [] }` and `files: ["index.d.ts"]` (paths in an extended config resolve against the base config, so this survives).
- Do **not** set `verbatimModuleSyntax` (it would force `import type` everywhere and mismatch the friendly strip default); `isolatedModules` already flags unsafe re-exports.
- On first run / `gnoblinctl types init`, write `~/.config/gnoblin/tsconfig.json` **only if absent**: `{"extends":"/usr/share/gnoblin/types/tsconfig.base.json","include":["./**/*.ts","./**/*.js"]}` (absolute `extends` path, so a package upgrade moves nothing the user owns). Also a `jsconfig.json` equivalent with `checkJs` for `init.js` users. Editors (VS Code, Zed, vtsls/neovim, the TS LSP) find `tsconfig.json` in the config dir and give completion/diagnostics for both `.ts` and `.js` (`// @ts-check`). Zero build step, nothing generated in the user's tree except that file.

**`gnoblinctl check [path]`** (two tiers, one command):

1. **Always, in-process, no Node needed**: load the module graph with the _same_ resolver/loader as the runtime (`--dry-run` staging, spec s18 steps 1-2), print oxc syntax diagnostics, unresolved relative imports, unknown `gnoblin/...` specifiers, duplicate declarations from `oxc_semantic`, and the runtime's validation errors with source-mapped locations. Exit 1 on failure.
2. **Types, optional**: locate `tsc` in order: `$GNOBLIN_TSC`, `<config>/node_modules/.bin/tsc`, `tsc` on PATH, `tsc6`, `tsgo`. Run `tsc --noEmit -p <config>/tsconfig.json --pretty` (create a temp tsconfig that extends the base if the user has none). Forward diagnostics; exit code from tsc. If none is found: print "type check skipped: install TypeScript (`npm i -g typescript`) or set GNOBLIN_TSC" and exit 0, unless `--types=require` is given. Flags: `--types=auto|require|off`, `--json`.

- Never invoked implicitly by the compositor or on reload (reload must stay fast and not depend on Node).
- TS 7 detail: `moduleResolution: node10`, `baseUrl`, `target: es5` are removed; our base config avoids all of them (verified list from the article above).

## 8. Recommendation

Use **oxc** (`oxc_parser` + `oxc_semantic` + `oxc_transformer` + `oxc_codegen`, exact-pinned `=0.158.0`) on **upstream rquickjs 0.14**, behind a small `TsCompiler` trait so the strip backend is swappable (oxc today; swc or dquickts later). One custom `Resolver`/`Loader` (s5), in-memory hash cache shared across hot-reload generations (s6), host-side source-map stack remapping keyed by absolute `.ts` paths (s4), generated `gnoblin.d.ts` + shipped base tsconfig for editor type-checking (s7), and `gnoblinctl check` running the real checks via an external native `tsc` (s7), **not** embedding the TypeScript compiler.

Spike before committing (all small): (1) measured `cargo bloat` delta and cold build time with only TS-related oxc features; (2) transform + run QuickJS on 3 fixtures: enum, namespace, parameter property, `satisfies`, `using`, standard decorator; confirm what oxc emits for each and what QuickJS rejects; (3) confirm `TransformOptions::from_target("es2023")` string and that TS stripping is on by default for `.ts` `SourceType`; (4) confirm `Resolver` trait signature and whether rquickjs 0.14 can install `Error.prepareStackTrace`.
