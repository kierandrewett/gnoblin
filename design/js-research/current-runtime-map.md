### Boot order the JS runtime must keep

1. Attach tree and drain snapshot. 2. Load library (stock shell). 3. Load user `init.ts` and its imports. 4. Fire `ready` for snapshot nodes (parents first). 5. Frame loop: apply batch, tick, send one transaction. Keep the one-in-flight + stale-retry rules unchanged (they are protocol behaviour, not Lua behaviour).

## Recommendation

Do not rewrite the protocol side. Extract the language-neutral part of `gnoblin-lua` (`tree_mirror.rs`, `tree_link.rs`, the transaction/resend loop in `ShellVm::frame`, `slot_link.rs` trait, `ClassSpec`/`tree_classes`) into a neutral crate, and put QuickJS bindings plus the ES loader and `.ts` stripping in `gnoblin-js` that reproduces `ShellVm::{new,load_shell,frame}` and `ShellSlot::from_env` one-for-one. Port `node.lua` and the 22 stock shell files to TS first (they are the spec's object model in embryo: `Node:extend`, `to`, `all/find`, `Seat:bind`), then add the genuinely new pieces: Workspace/Layout split with stable ids and generation hot reload, style cascade, display/mirror/span, interactive transitions, and the `.so` extension manager. Keep `gnoblin-config`; decide pattern syntax for rules.

## Open risks

1. **Hot reload (§18) has no precedent** here. The shell loads once; user-file failures keep partial effects. Needs generation staging plus atomic transact; stable user IDs are not native today.
2. **Instruction budget**: QuickJS has an interrupt handler, not a Lua-style instruction counter. The 10M/100M instruction budgets and the stated "never fail for machine load" property need a different mechanism; unverified for the chosen binding.
3. **Lua patterns in config rules**: `gnoblin-config` depends on `gnoblin-lua-pattern` today. Changing syntax breaks existing configs and `window_rule.md`.
4. **Two hosts**: the config host (`init.lua` to document) and the shell VM must both move; spec merges them into one `init.js`. Config validation/last-good/`gnoblinctl config validate` currently depends on evaluating Lua in a throwaway host (`check.rs`).
5. **Spec says runtime is a restartable client**: matches today's role, but stale comments in `gnoblin-compositor/Cargo.toml` suggest the compositor still links `gnoblin-lua`; verify no in-compositor Lua remains before deleting.
6. **Legacy C/Mutter tree** (`src/`, `patches/mutter/`, `tests/*.c`, `lua-runtime.yml`) still names Lua heavily; whether it is in scope for the swap is the owner's call.
7. Files I did not open (listed as _unverified_ above): `docs/user-shell.md`, most `docs/shell-api/*`, `design/archive/lua-api.md` body, the minor crates with Lua mentions, `crates/gnoblin-wasm` beyond a directory listing.
