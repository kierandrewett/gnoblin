# Performance baseline: the Rust candidate, stock Mutter 51.0 and the legacy Gnoblin, headless
#
# Produced:   2026-11-15 on an Agent37 instance: 4 cpus, 8192 MiB, gVisor kernel 4.19.0-gvisor. Not real hardware.
# Command:    gnoblin-parity perf <target> --json <file>, once per target, as root, with the environment of the full parity
#             run (tests/parity/reports/2026-11-15-agent37-all-targets.txt). Exit code 0 for all three.
# Method:     frame time = gaps between frame callbacks of one window redrawing for 5 s. Key latency = EIS key press to the
#             client's wl_keyboard.key (key->client) and to the next frame callback after a redraw (key->frame), 100 keys.
#             Idle CPU = CPU ticks of every process of the session over 10 s with 0 and with 50 windows mapped. RSS = the
#             largest process of the session at 0, 10 and 50 windows, read from /proc from outside the process.
# Reading it: the candidate runs in the runner's own process (`gnoblin-parity serve-candidate`), the Mutter targets run as
#             separate processes, so the RSS figures measure different things. Mutter paces frame callbacks at its virtual
#             monitor's 60 Hz (mean 16.7 ms); the candidate's callbacks come at a mean of 3.9 ms, faster than 60 Hz, so its
#             frame time is not a refresh-paced number [INFERENCE: the candidate's headless pacing was not read in code].
#             Idle CPU is accounted in whole ticks under gVisor, so values from 0.0 to 1.1 % are noise.
#             Earlier runs of this baseline on mutter51 and mutter-gnoblin lost every key. That was a harness bug fixed in
#             the same change (the EIS sender decoded the seat's capability mask by position), not a property of the targets.
# Limits:     headless: no panel, so the frame callback is the compositor's own presentation signal, not photons; software
#             rendering; the input is EIS injection, which skips libinput and the kernel's input path; one run per target,
#             so the figures show the spread inside that run and not between runs.
