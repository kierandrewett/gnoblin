Red runs of the memory budget's tests (lane GpuBudget, issue gnoblin-4z5 stays open)

What this shows: each test below FAILS on a copy of the tree in which one piece of the budget is switched off, and
passes on the tree as committed. It is "red with the check off", not "red before the code existed": the tests were written
beside the enforcement, so no commit has them failing against a tree that lacks it. The switches are environment
variables read in a copy of the tree on the Agent37 box (the box resets its tree on the next sync); nothing of them is
committed.

Switches:
  admission off (GNOBLIN_RED)            admit_buffer, admit_growth and admit_surface admit every request
  releases skipped (GNOBLIN_RED_LEAK)    release_buffer and release_surface give nothing back
  eviction off (GNOBLIN_RED_NOEVICT)     an admission that counted on caches never frees them
  publication off (GNOBLIN_RED_PUBLISH)  the session numbers are never put on the screen nodes
  publication noisy (GNOBLIN_RED_NOISY)  gpu_memory_refused_total changes on every publication
  noisy clients (GNOBLIN_RED_NOISY_CLIENTS)  gpu_memory_clients_bytes changes on every publication
  configuration ignored (GNOBLIN_RED_CONFIG)  the bounds are always the defaults, whatever the section says
  dmabuf recorded early (GNOBLIN_RED_RECORD_EARLY)  a GPU buffer is counted before the importer answers
  DRM accounting wrong (GNOBLIN_RED_DRM) allocated() counts no slot, scanout_bytes ignores the slot count, plus() adds nothing
  zero bound (GNOBLIN_RED_ZEROBOUND)     a bound of 0 is a bound of 0 bytes instead of no bound
  record adds (GNOBLIN_RED_RECORD_ADDS) a buffer recorded again under its id is added instead of replacing the old one
  measurement without capture (GNOBLIN_RED_NOCAPTURE)  the loop's measurement leaves out the frames capture keeps
  error code 1 (sed of the constant)     NO_MEMORY is 1 instead of the protocol's 2
